# REVIEW.md

Defects found in the starter `app/main.py` (line numbers refer to the original starter).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` (l.22) | Client is not `tz_aware`, so PyMongo returns **naive** datetimes. Any later `.timestamp()` or IST conversion treats them as server-local time. | On a server not running in UTC, a punch stored as 04:30Z comes back shifted by the server's offset when converted to epoch ms. | `MongoClient(..., tz_aware=True, tzinfo=UTC)`; all conversions go through `to_ms` / `from_ms`. |
| 2 | Module level | **No indexes are created**, even though the contract requires them at startup. There is no unique index on `employees.emp_code` or on `attendance_logs(emp_code, date)`. | `db.attendance_logs.getIndexes()` shows only `_id`; explain shows `COLLSCAN`; duplicates are possible (see #9, #13). | `ensure_indexes()` runs in the FastAPI lifespan (idempotent) and is retried from `/health` if Mongo was down at boot. |
| 3 | `health` (l.72) | Always returns 200 without talking to MongoDB. | Stop mongod: `/health` still says `ok`. | Runs `ping`; returns 503 `{"detail": ...}` on failure. A 5 s `serverSelectionTimeoutMS` stops it hanging for 30 s. |
| 4 | `compute_late_minutes` (l.33) | (a) It builds shift start from the punch's own (naive, server-local) date and time, not IST. (b) It compares **floored minutes** `> 10`, so anything from 10:01 to 10:59 after start is treated as on time. (c) It ignores overnight shifts. | (a) Server in UTC: punch 09:45 IST = 04:15 UTC, replaced to 09:30 "UTC", gives a negative value and 0 late. (b) Shift 09:30, punch 09:40:30: floor is 10 → 0, but R2 says 10. (c) Shift 22:00-06:00, punch 01:00: same-day 22:00 gives a negative value and 0 late, expected 180. | Compares **seconds** `> 600` against the IST shift start of the attendance date (R1), then floors to minutes. |
| 5 | `compute_work_hours` (l.40) | Uses Python `round` on a float, which is not half-up (float representation and banker's rounding). There is also no second truncation. | 16182 s = 4.495 h → `round(4.495, 2)` = 4.49 (float is 4.49499…), so `half_day` becomes **true**. R4/R5 give 4.50 and false. | `Decimal(seconds)/3600` quantized with `ROUND_HALF_UP`, on second-truncated instants. |
| 6 | `compute_overtime` (l.44) | (a) No 30-minute minimum (R3). (b) For an overnight shift, the shift end is put on the **same** day instead of the next. (c) It mixes the naive punch (starter) with an aware `end`, so the subtraction raises `TypeError` (500). | (a) 5 min after shift end returns 5, expected 0. (b) Shift 22:00-06:00, out 06:40 next day: compared with 06:00 on the start day gives 1480, expected 40. (c) Any call with a naive datetime crashes. | `shift_bounds()` adds a day when `end <= start`; returns `minutes if minutes >= 30 else 0`. |
| 7 | `EmployeeIn` (l.53) | No validation: `emp_code` pattern, email, name/department lengths, `HH:MM` shift format, a real `joined_on` date, and `shift_start != shift_end` are all unchecked. | `POST /employees` with `joined_on: "yesterday"` or `shift_start: "25:99"` returns 201 and later breaks R1/R2 with a 500. | Pydantic constraints that mirror `EmployeeCreate` in openapi.yaml, plus a validator for `shift_start != shift_end`. |
| 8 | `PunchInIn` (l.63) | `punched_at: Optional[int]` is lax: it accepts `"1783312500000"`, `1783312500000.0`, `true` and seconds-sized values. `status: str` accepts `ABSENT`, `LEAVE` and garbage. | `punched_at: 1783312500` (seconds) is accepted and stored in 1970; `status: "FOO"` returns 201. | `StrictInt` with `ge=1e11, le=4102444800000`; `status: Literal["PRESENT","WFH","ON_DUTY"]`. |
| 9 | `create_employee` (l.77) | Check-then-insert with no unique index is a race, so two concurrent creates both succeed. | 8 parallel POSTs with the same `emp_code` give several 201s and duplicate rows. | Insert straight away and map `DuplicateKeyError` from the unique index to 409. |
| 10 | `create_employee` (l.81) | `created_at = datetime.now()` is naive local time, stored as if it were UTC (wrong instant), and it is returned as an ISO string instead of epoch ms. | On an IST server, `created_at` is 5h30 in the future; the response field is `"2026-..."`, not an integer. | `datetime.now(UTC)` (ms precision), returned via `to_ms`. |
| 11 | `list_employees` (l.93) | `skip = page * page_size` skips the first page. | `page=1` returns employees 21-40; with ≤ 20 employees it returns `[]`. | `skip = (page - 1) * page_size`. |
| 12 | `list_employees` (l.94-95) | `total` counts the **whole** collection and ignores the filter. There is **no sort** by `emp_code`. `page` and `page_size` are unvalidated: `page=0` gives a negative skip and a 500, `page_size=0` means "no limit", and 1000 is allowed. `created_at` leaks as a datetime. | `?department=Sales` gives `total` = all employees; order follows insertion order; `?page=0` returns 500. | `count_documents(q)`, `.sort("emp_code")`, `Query(ge=1)` / `Query(ge=1, le=100)`, `employee_out()` serializer. |
| 13 | `punch_in` (l.101) | Unknown employee: `emp` is `None`, so `emp["shift_start"]` raises `TypeError` and returns **500** instead of 404. | `POST /attendance/punch-in {"emp_code":"EMP9999"}` returns 500. | `get_employee_or_404()`. |
| 14 | `punch_in` (l.102-103) | `datetime.fromtimestamp()` uses the **server's** time zone (naive), and `date` is the server-local calendar day, not IST. There is no overnight-shift rule (R1) and no truncation to whole seconds. `if body.punched_at` treats 0 as "now". | Server in UTC, punch 02:00 IST on the 7th: stored date is the 6th (UTC date). Overnight punch at 01:00 lands on the wrong day. 09:40:00.900 is stored with ms. | `from_ms()` truncates to seconds and returns aware UTC; `attendance_date()` implements R1 in IST. |
| 15 | `punch_in` (l.104) | Check-then-insert race with no unique index, so two identical concurrent punch-ins both get 201. | 10 parallel identical punch-ins give several 201s and duplicate (emp_code, date) docs. | Unique index on `(emp_code, date)`; `insert_one` and `DuplicateKeyError` give 409. |
| 16 | `punch_in` response (l.119) | Returns `"id"` (the ObjectId string), which the contract forbids, and returns `punch_in` as a datetime rather than epoch ms. | Response contains `id` and `"punch_in": "2026-07-06T..."`. | `record_out()` serializer: no id, instants as ms, defaults for legacy fields. |
| 17 | `list_attendance` (l.142) | `list(find(q))` loads **every matching document** into memory and sorts in Python. That is O(N) memory and time at 100k docs, and it uses no index. | Slow and memory-hungry at 100k records; explain (if any) shows `COLLSCAN`. | Database-side `.sort([date -1, emp_code 1]).skip().limit()` backed by indexes; `count_documents` for `total`. |
| 18 | `list_attendance` (l.143) | Sort is by `date` only; the tie-break by `emp_code` asc is missing, so page contents are non-deterministic between pages. | Same-date rows come back in arbitrary order, and an item can appear on two pages or none. | Compound sort `date desc, emp_code asc`. |
| 19 | `list_attendance` (l.131-140) | No validation: `date_from`/`date_to` are not checked as dates, `date_from > date_to` is not a 422, `status` is not checked against the enum, and `page`/`page_size` are unbounded. `if emp_code:` silently ignores an empty value. | `?date_from=07/01/2026` returns 200 with nonsense; `?status=LATE` returns 200 `[]`; `?page_size=100000` is accepted. | `parse_date`, explicit 422 for `from > to`, `Literal` status, `Query` bounds, `is not None` checks. |
| 20 | `list_attendance` (l.147) | Leaks `id`; instants are returned as datetimes; legacy docs without `history`/`half_day` are returned without those fields. | Record 9 from the sample lacks `history` and `half_day` in the response. | `record_out()` fills `[]` / `false` / `0`. |
| 21 | Missing endpoints | `punch-out`, `PATCH` regularize, the four analytics endpoints and `/admin/explain` are not implemented. | 404 / 405 on every one of them. | Implemented (see README). |

**Looked at and decided were not defects**

- `load_dotenv()`: its default is `override=False`, so real environment variables already win over `.env`. I made it explicit (`override=False`) for readability, but it was correct.
- `IST = timezone(timedelta(hours=5, minutes=30))`: correct; IST has no DST, so a fixed offset is right.
- `doc.pop("_id", None)` after `insert_one` in `create_employee`: correct (insert mutates the dict). Kept the idea via a dedicated serializer.
- `db.employees.find(q, {"_id": 0})`: excluding `_id` with a projection is correct.
- The helper **signatures** were reasonable to reuse, but their bodies were wrong (#4-#6). I kept the helper names and rewrote them to take the employee plus the attendance date, because late/overtime depend on which shift a punch belongs to (R1), not just on the punch's own date.
